# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Use `python3` (no `python` alias on this machine). Run everything from the repo root: tests import `src.crossword.visualize` and `src.crossword.sandbox`, which only resolve from there.

```bash
pip install -e ".[dev]"                 # install package + pytest
python3 -m pytest tests/                # run all tests
python3 -m pytest tests/test_visualize.py::SandboxPageTests::test_typing_mode_is_wired_up   # single test
python3 -m unittest tests.test_visualize   # works without pytest installed (tests are unittest.TestCase)
./crossword                              # sandbox opened in the browser, schemas saved in schemas.json
PYTHONPATH=src python3 -m crossword.visualize --store other.json   # same, with any schemas file
PYTHONPATH=src python3 -m crossword.visualize   # no store file: schemas go to localStorage
python3 -m build                         # build wheel/sdist into dist/ (needs `pip install build`)
```

There is no linter or formatter configured.

## Architecture

This branch is the sandbox only. The automatic generator (`crossword.py`, the `/generator` page and static HTML output) is kept on a local `with-generator` branch, which also has the upstream history. It is not published.

`src/crossword/visualize.py` holds the shared page shell (`page`, `STYLE`) and the server. `main` always serves: it runs a stdlib `http.server` on 127.0.0.1 and opens the browser, through `explorer.exe` on WSL and `webbrowser` elsewhere. `--serve` and `--sandbox` are hidden no-op aliases from when there were other modes. `GET /` serves `src/crossword/sandbox.py`'s page, and the old `/sandbox` URL redirects there. Each `GET /` reloads `visualize` and `sandbox` (`render_page` in `serve`), so edits to the page's HTML/CSS/JS show on a browser refresh; if the reload fails (say, a half-saved file) the last version that loaded is served. Changes to the server code itself (`serve`, `Handler`, `main`) still need a restart.

The schema bar at the top picks and manages schemas (select, New, Duplicate, Rename, Clear, Delete) and scrolls away; below it, one sticky toolbar holds the tools for the current schema (word, grid and view groups, plus a Help popover). The sandbox page is a client-side-only grid: you drag a word, press H/V to turn it, add or remove edge rows/columns, edit black cells by hand (Edit black cells, B), and type new words by clicking an empty cell. There is no separate word pool: a schema's words are the ones in its grid, and the sidebar lists them (filled in by the script from `order`), so taking a word out of the grid also drops it from the list. The sidebar sits in a `.board-row` beside the board: its content is absolutely positioned (`.side-inner`), so the row's height comes from the board alone and the list scrolls within it. Each word gets black cells at both ends. On screen, the cells walled in by letters are black. Every other non-letter cell is grey: `outsideSet` starts from the non-letter cells on the edge of the grid and spreads to any non-letter cell sharing a full side (not a corner) with one. Only letters stop it; hand-painted cells let it through and, when reached, are drawn grey like the rest (not counted). Those grey cells are the schema's external cells, darker grey (`.end`), when they lie within the schema's area (the rectangle from the topmost, bottommost, leftmost and rightmost letters, so a grid side with a letter on it is the schema's margin) or at the ends of a word (`blocksOf`: left and right of an across word, above and below a down word; the cells along a word's sides are not ends). The rest are beyond the schema, light grey; a schema whose letters reach all four sides has none. In paint mode, hand-painted cells get a ring (light on black cells, dark on grey ones). The Grid group's External as black toggle (A, the schema's `allBlack`, saved with it) is for full rectangular schemas: every non-letter cell is black and counted. The black cells are numbered in reading order. The status bar (white on dark grey, under the toolbar) holds the grid size as two number inputs (`setSize`: lines come and go at the bottom/right, or the top/left when letters hold that side), the black-cell count, and the black share (black / (black + letter cells)), green up to 15%, orange up to 22%, red above, with an (i) that lists those thresholds on hover. Then the number of words and the share of them with no definition (rounded up, red unless 0%, hidden when the grid has no words). While editing black cells or typing, it shows instructions instead. The save state (`#saved`) sits in the page's top-right corner beside the title, red when saving failed. Words may touch the edge of the grid, so their end black cells can fall outside it (`blockSet` keeps only the cells inside the grid). Letters are the only thing that stops an edge row or column from being removed (`canShrink`). The Grid group's Trim (T, `trim`) removes every outer row and column without a letter, on all four sides, down to the 2-line minimum. The toolbar's View group has five toggles, each with a key (`VIEWS`): Letters (L), Numbers (N, the word numbers in the grid), Black numbers (M, the black-cell count numbers), Wordlist (W, the word list) and Definitions (D, the clues panel). They live in the script's `view` and are remembered in `localStorage`, not in the schemas, except Wordlist, which is always on when the page opens. Sidebar words without a definition are in italic (`.no-def`), and an (i) beside the WORDLIST heading explains the list. Clicking a sidebar word selects it and opens the definition popup (`#def-dialog`, a native `<dialog>`): Save writes it, while ×, Cancel, Esc or a click on the backdrop close it unchanged. The page always spans the full width (`page(..., wide=True)`); the grid and the word list beside it (or the grid alone) are centred together in `.board-row`.

The sandbox keeps several named schemas and clue definitions, saved through `POST /store` into the `--store` file (`schemas.json` for `./crossword`, see `read_store`/`write_store`), or in `localStorage` when there is none. Schemas saved by older versions may carry a `typed` list; the page drops it on the next save. The package has no runtime dependencies.

`schemas.json` and build artifacts (`dist/`, `*.egg-info/`, `__pycache__/`) are git-ignored, because the schemas are personal. `words.md` and `*.sandbox.json` stay ignored for checkouts from before the words file was dropped.
